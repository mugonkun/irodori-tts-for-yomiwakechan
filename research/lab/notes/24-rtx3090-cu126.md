# 24 — RTX 3090 機の CUDA 実測（キット cu126・司令官が実行・第 1 回収）

> 席＝Fable（主席）が回収して整理。実行＝司令官が 3090 機で `run-cuda-kit.ps1 -Variant cu126` を **N:\ 上で直接**走らせた（ローカルコピーなし＝各条件でモデルを NAS から読み直すため 167 分）。
> 回収物＝`lab/out/3090-results-0609/`（`summary.md`・`env.json`・`install.json`・`bench_cu126_*.json`・`compile.json`・`onnx_cuda.json`・`onnx_dml.json`・`steps.json`・`logs/`・`wav/`）。数値は `summary.md`（キットが自動生成・`21` §5 の読み方）から転記。

## 要点（10 行以内）

1. **機体**＝RTX 3090（24 GB・compute 8.6・**ドライバ 591.86**）・i9-12900K・RAM 63.8 GB・Windows 11（build 26200・表記は "Windows 10 Pro 25H2"）・PowerShell 5.1。
2. **導入**＝`torch 2.10.0+cu126`（cuDNN 9.10.2）が pin のまま入り `cuda.is_available()=True`。venv **4,478 MB**・`torch/` 3,937 MB（cu126 は本機の cu130 3,192／2,650 MB より 1.3 GB 重い）。**ドライバ 591.86 ≥ 560.76**＝cu126 の Windows 要件を満たす。
3. **合成（常駐ウォーム・bf16）**＝短文 40 steps **0.722 s／RTF 0.192**、長文 **0.867 s／RTF 0.079**、10 steps 短文 0.518 s／0.138・長文 0.576 s／0.053。**司令官機 ROCm bf16（短文 0.749／長文 1.729）と短文は同等・長文は 2 倍速**。
4. **fp32 も正常**＝短文 40 steps 0.851 s／RTF 0.226・長文 1.62 s／0.148。`decode_latent` は 31〜100 ms（**ROCm fp32 の 1,977 ms の病的な遅さは CUDA では無い**）＝CUDA では bf16 は「速いから選ぶ」であって必須ではない。
5. **コールド罰が軽い**＝短文 40 steps cold 1.44 s→warm 0.851 s（1.7 倍）・bf16 1.098→0.722（1.5 倍）。ROCm の「初見形状で 3〜12 倍」は CUDA では出ない。
6. **VRAM ピーク**＝bf16 **3,079 MiB**（司令官機と同値・長さに依らない）・fp32 4,134（短文）／4,682 MiB（長文）。
7. **段別（bf16 短文 40・warm）**＝predict_duration 35 ms／**sample_rf 647 ms（90%）**／decode 22 ms／watermark 16 ms。3090 と 8060S で sample_rf がほぼ同じ（647 vs 626 ms）＝短文・小バッチではカーネル起動が支配し、GPU の格が効いていない。長文では 735 vs 1,438 ms で 2 倍。
8. **`torch.compile` は CUDA でも失敗**＝逐語 `TritonMissing: Cannot find a working triton installation.`（`07` §3・`21` §3 の見立てどおり。CPU は `cl` 不在・CUDA は Triton 不在）。
9. **ONNX の CUDA EP は全グラフが CPU に落ちた**（`onnx_cuda.json`＝`ep_fallback`）。`logs/onnx-cuda.log` の逐語＝`Error loading "N:\…\onnxruntime_providers_cuda.dll"` と `Failed to create CUDAExecutionProvider. Require cuDNN 9.* and CUDA 13.*, and the latest MSVC runtime.`。nvidia-* wheel（cudnn-cu13 9.25.1.1・cublas 13.6.0.2 等）は入っている＝**ORT ≥1.21 の Windows で要る `onnxruntime.preload_dlls()` を bench が呼んでいなかった**のが原因候補（`bench_onnx.py` を修正し `run-onnx-only.cmd` で再走を依頼）。**CUDA EP の数字は未取得**。
10. **DirectML EP（3090）**＝`dit_step` fp32 **45.0 ms**（B=3・8060S の 80.6 ms の 1.8 倍速・CPU EP 差 2.5e-5）、`duration` 2.7 ms、**`dit_step_fp16` は max abs diff 6.2＝AMD と同じく数値が壊れる**。`encode_conditions`（allowzero）・`dacvae_decoder`（ConvTranspose1d）・`speaker_encoder` は無手術グラフでは落ち、透かしは DFT でロード不可＝**`23` の AMD での所見がベンダ非依存であることの実証**。手術版（`*_az0`・`*_dml`）は N:\ の `onnx/` に追加済み＝再走で取れる。
