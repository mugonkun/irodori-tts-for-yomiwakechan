# 27 — RTX 3090 機の第 3 回収（SSD 上で cu130 を再走・軽量キット `kit-ssd`）

> 席＝Fable（主席）が回収して整理。実行＝司令官が `kit-ssd`（63 檔・7.7 GB・uv キャッシュと venv を含まない）を `C:\kit-ssd\` に写し、`run-cu130.cmd` を **ローカル SSD 上で**走らせた（結果は `sync-results.cmd` が 1 分ごとに `N:\irodori-native-research\results-ssd\` へ写した）。
> 回収物＝`lab/out/3090-results-ssd-cu130/`（`summary.md`・`install.json`・`bench_cu130_*.json`・`compile.json`・`onnx_cuda.json`・`onnx_dml.json`・`steps.json`・`logs/`・`wav/`）。数値は `summary.md` から転記。

## 要点（10 行以内）

1. **全段 6.2 分で完走**（N:\ 直走行の 138.5 分の 1/22）。導入＝venv 2.7 s・torch cu130 の PyPI 取得＋導入 **36.1 s**（wheel 1,781 MiB・3090 機の回線）・残り依存 28.1 s・`d_torch_guard`（`import torch`）**1.8 s**（N:\ では 311〜563 s）。`24`/`25` の遅さは NAS 越しの DLL 読みで確定。
2. **cu130 bf16 短文 40 steps の異常値（`25` の 1.496 s・cold<warm の逆転）は消えた**＝warm **0.808 s／RTF 0.215**・cold 1.032 s（順序正常・cold/warm 1.28 倍）。`25` §要点 2 の「cu130 の bf16 GEMM 経路の差」は棄却＝**NAS 上の走行ノイズ**だった。cu130 を既定にする条件（ローカル SSD での再走）は満たされた。
3. **SSD の合成値は NAS 値より全体に速い**（1.1〜1.7 倍）＝以後の CUDA の基準値はこの表（表 1）。bf16 長文 40 steps 0.917 s／RTF 0.084、bf16 10 steps 短文 **0.300 s／0.080**・長文 0.422／0.039。fp32 短文 40 steps 0.875／0.233・長文 1.563／0.143。
4. cu126（`24`・NAS 走行）との比較は**同条件ではない**＝bf16 短文 40 steps は cu126(NAS) 0.722 vs cu130(SSD) 0.808（12 % 差・NAS 側が不利な条件でこの差なので cu130 が遅い可能性は残るが RTF はどちらも 0.2 級＝裁定には効かない）。cu126 の SSD 再走は「両者の優劣」を詰めるときだけ。
5. VRAM ピークは同値（bf16 3,079 MiB・fp32 4,134／4,682 MiB）。段別（bf16 短文 40・warm・ms）＝predict_duration 38.1／sample_rf 705.7／decode 22.4／watermark 16.4。
6. `torch.compile`＝SSD でも `TritonMissing`（3 回目・確定）。
7. **ONNX の CUDA EP（ORT 1.29.0）は `25` と同値**＝`dit_step` 30.8 ms・`encode_conditions` 35.2 ms・`dacvae_decoder` 38.1 ms・`silentcipher_watermark` 48.1 ms・`duration` 2.2 ms・`dit_step_fp16` 21.8 ms（差 6.20＝破綻・再現 3 回目）。ORT CUDA venv **1,787.9 MB**（`onnxruntime-gpu[cuda,cudnn]`＝cuDNN 込み）・ORT DirectML venv **138.8 MB**。
8. **DirectML（ORT 1.24.4）も `25` と同値**＝`dit_step` 47.3 ms・`encode_conditions_sdpa_az0` 442 ms・`dacvae_decoder_fp32_dml` 86.6 ms・`duration` 2.9 ms。無手術の `encode_conditions_sdpa` は CPU 落ち（700 ms）・無手術デコーダは run 失敗（bench 側のエラー文字列復号が cp932 で落ちた＝`UnicodeDecodeError`・記録の欠けであって結果は `25` と同じ）・透かしはロード不可（DFT）。
9. `kit-ssd` の設計＝ONNX 本体 3.9 GB＋モデル 3.4 GB＋スクリプトのみ。torch・CUDA ライブラリ・Python は 3090 機で uv が PyPI から取る（要ネット）。`kit-cuda` の丸ごとコピーは uv キャッシュと venv（数十万檔）で数時間かかるため不可＝キット README の最上段に明記。
10. 未実施＝⒝の端から端まで（`onnx-e2e/run-onnx-e2e.cmd`・`26` のキット・司令官の実行待ち）・cu126 の SSD 再走（優劣を詰める場合のみ）。

## 主席への注意

- 報告の CUDA 表は本表（SSD）を基準値にし、`24`/`25` の NAS 値は「NAS 越しの走行で 1.1〜1.7 倍遅い」と注記して残す。U-4（cu130 異常値）は閉じる。
- cu130 既定・cu126 退路の裁定条件は満たされた。cu126 との厳密比較は未（NAS 対 SSD）だが RTF は同級。
- ⒝の判断則（DirectML RTF≤0.5・40 steps・fp32）は NVIDIA でも端から端までの実測待ち（`26` のキット）。段合計の見立て（DirectML ≈0.6・CUDA EP ≈0.28）は据え置き。
