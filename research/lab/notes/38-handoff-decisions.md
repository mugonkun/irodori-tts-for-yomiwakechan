## 0. 要点（10 行）

1. **要求 8 項のうち、上流のまま満たせるのは 3 項半**。⑴Python 不要（実射済み・`30`）・⑸CPU 合成（fp32 強制で可）・⑺参照ボイス＋名付け（**日本語名は alias 経路だけ**）・⑻「デフォルト」（alias の `no_ref` で成立・実射 4）。
2. **満たせないのは⑷「設定可能パラメータ一覧の取得」**＝上流に一覧 API は無い。`/openapi.json` は無認証で取れるが **44 欄に既定値も min/max も無い**（enum のみ）＝**新リポが自前のパラメータ表を持つのが必須**（実射 14）。
3. **話者名の日本語は「置き方」で通り／通らずが割れる**＝`voices.json` の alias・檔名スキャン・`IRODORI_DEFAULT_VOICE` は**通る**（実射 2・3・12）が、**voice CRUD API は ASCII 限定** `^[A-Za-z0-9_-]+$`（`voices.py:24,151-155`）＝日本語名は POST/GET/PUT/DELETE が**全部 400**（実射 6・7・9・10・11）。

5. **「UI で GPU／CUDA 版を選ぶ＝暗黙で本体の読み上げにも効く」は、起動主体を本体の元栓から配布アプリへ移す**という意味になる。報告 §6-3 の A3（元栓が env 注入）と**排他**＝ここが最大の新規決定。
6. **CUDA 版 2 系統を UI で選ぶ**＝cu126（DL 2,470 MiB）と cu130（1,781 MiB）は**別の site-packages 木**＝同梱なら実行系が ≈2.1→≈4.4 GiB、後から取得なら初回にネット必須。**速度は同値**（3090 で RTF 0.21 級・`24`・`27`）＝差はドライバ要件とサイズだけ。
7. **精度の既定は上流 fp32**（`config.py:29-30`）で、**GPU が見えないと黙って CPU に落ちて 340 倍遅い**（`29` §2-2）。bf16 は GPU 不在なら**起動時に ValueError**＝安全装置。**device と precision は必ず 4 本セットで組む**（`model`／`codec` × `device`／`precision`）。
8. **透かしは上流パッチ無しで切れる**＝`silentcipher` を同梱しない／重みを置かないだけで `ready=False`・合成は 200・応答 messages に警告が乗る（`watermark.py:33-52`・`inference_runtime.py:1433-1446`）。切る／残すはライセンスではなく製品姿勢の裁定（報告 §0-2 の 3）。
9. **配布既定が危ない**＝Server 既定は `host=0.0.0.0`・`api_key=None`・`empty_cache_interval=10`・`preload=false`（`config.py:18-20,35,39`）＝**LAN 公開・無認証・15 秒スパイク・初回合成に読込が乗る**。配布物は 4 つとも焼き直す（推奨）。
10. **止まる決定は 4 件だけ**（配布経路 U-8／法解釈 U-2・U-15／cu126 の古ドライバ実効 U-14／起動主体）。他の未確認（U-3・U-5・U-9・U-12 等）は**新リポの着工を止めない**。

## 2. 要求 8 項の逐条検分

### 要求① Python を知らなくても導入できる

- **事実**＝公式 embed 3.12.10 に `python312._pth` の 3 行を書くだけで Server が起動し `/health` 200・`PRELOAD=true` で `runtime loaded in 28.16s`（`30` §0-3・報告 §10-1）。`sys.executable` 再実行・`multiprocessing`・`pkg_resources` は grep 0 件（`30` §1-A）。手順は 21 → **6 操作**（報告 §5-1）。
- **成立するか**＝**する**（実射済み）。
- **制約・落とし穴**＝⑴ `msvcp140.dll`（embed zip に無い・`torch/__init__.py:237-240`）＝`vc_redist.x64.exe` 25 MiB 同梱。⑵ `.env` と `voices_dir` が **CWD 相対**で、`voices_dir` は**起動時に mkdir**＝読取専用フォルダに置くと起動で落ちる（`config.py:13,41`・`voices.py:58-60`）。⑶ `*.dist-info` の同梱が要る（transformers が `importlib.metadata.version()`）。⑷ パスは `._pth` 専管・`PYTHONPATH` は無視、設定は env（`30` §1-B）。⑸ 初回モデル取得 ≈3.3 GiB は残る。
- **本体が決めること**＝配布経路（実行系 ≈2.1 GiB＞GitHub Releases の 1 資産 2 GiB）・vc_redist をインストーラが黙って通すか。
- **受け入れ条件**＝Python 未導入・torch 未導入の Windows 11 実機で、**利用者操作 ≤ 6**（vc_redist 自動なら ≤ 5）で `/health` が 200 になること。初回起動から ready まで **≤ 120 s**（モデル取得済みの状態で。CPU embed の実測 28.16 s に安全率）。

### 要求② 本体から独立した配布パッケージ＋UI を持つアプリ

- **事実**＝上流に UI は gradio（`gradio_app*.py`）しかなく、**device 引数ゼロ・env も読まない**（`gradio_app*.py:642-645,660-663`）＝報告 §4 の結論「⒜⒞とも Server を土台に」。Server の CLI は `--host/--port/--reload` の 3 つだけ（`__main__.py:17-21`）。停止は **kill のみ**（graceful ルート無し・`30` §2-4）。
- **成立するか**＝**する**（Server＋自前 UI）。gradio を UI に使うのは GPU 指定で不利＝**推奨しない**。
- **制約・落とし穴**＝⑴ Server 既定が `0.0.0.0`・無認証＝**配布物は 127.0.0.1 と api_key 生成に焼き直すべき**（推奨）。⑵ UI と Server を 1 プロセスに畳むと「1 プロセス 1 デバイス」（`runtime.py:48`）が UI ごと縛る＝**UI は別プロセス・Server は子プロセス**が素直（推奨）。⑶ ログは stderr が本命・stdout はバッファで順序が狂う（`30` §2-5）。⑷ `IRODORI_CORS_ORIGINS` は JSON 配列必須（カンマ区切りは起動即死）。
- **本体が決めること**＝ポート（8088 は稼働機の既存個体と衝突する）・UI の常駐可否・停止の作法（kill しかない）・アップデート配布の形。
- **受け入れ条件**＝配布物を**別フォルダに 2 個同時に置いて別ポートで同時起動**しても互いを壊さないこと（`voices_dir`・`HF_HOME`・ポートが独立）。UI 起動から Server ready まで **≤ 120 s**、UI の停止操作から**プロセス消滅まで ≤ 10 s**・**VRAM が idle 値に戻る**（`29` §6-2＝kill 8 秒後に idle と同値）。

### 要求③ VOICEVOX のような単体 TTS として扱える

- **事実**＝口は OpenAI 互換（`POST /v1/audio/speech`）。出力はモノラル 48 kHz 16bit（`06` 要点 9）。VOICEVOX の `/speakers`＋`/audio_query`＋`/synthesis` に当たるものは**ない**＝話者一覧は `/v1/audio/voices`（id と参照ファイルだけ）、パラメータ表は無し。
- **成立するか**＝**「単体で叩ける HTTP TTS」としては成立**。**「VOICEVOX と同じ形」は成立しない**（新リポが口を足すか、本体が OpenAI 形に合わせるか）。
- **制約・落とし穴**＝⑴ 同時実行は 2 段の直列化（`Semaphore` 既定 1＋ランタイム内 `threading.Lock`）＝**並列合成はできない**（`06` 要点 7）。⑵ キャンセル不可・進捗なし＝中止の粒度はチャンク（`14` T-5）。⑶ 未知欄・綴り違いは**沈黙**（トップレベル経路は `Literal` 検査も回避）＝**白名簿検査が必須**（`14` T-2・T-3）。⑷ `X-Irodori-Seed` は複数チャンクで再現不能（T-4）。⑸ エラー body にサーバの絶対パスが漏れる（T-8・本便 13b で再現）。
- **本体が決めること**＝新リポの口を「OpenAI 互換のまま＋独自 `/params` を足す」か「VOICEVOX 風に作り直す」か。
- **受け入れ条件**＝curl 1 本（Bearer 込み）で wav が取れること。未知欄・綴り違い・範囲外を**400 で弾く**（沈黙 0 件・現状は 4 通りとも 200）。エラー body に**絶対パスを 0 件**にすること。

### 要求④ 本体から設定可能パラメータ一覧を取得できる

- **事実**＝**一覧 API は無い**。`/v1/models` は 1 件を返すだけ（`app.py:203-215`）。`/openapi.json` は**無認証で 200**・`IrodoriOptions` 44 欄の**名前と型と enum だけ**で、**既定値 0 欄・min/max 0 欄**（本便 実射 14）。範囲を持つのは `speed` と `input` の 2 欄のみ。既定値は dataclass／Server env／checkpoint の 3 段に散っている（§1 補）。
- **成立するか**＝**上流のままでは成立しない**。新リポが `GET /params`（仮）を足すか、配布物に静的な JSON を同梱すれば成立。
- **制約・落とし穴**＝⑴ 本体の器は `ParamKind`＝Number／Choice／Flag／Text（`Core/Models/Capabilities.cs:8-20`）で、**`IsFullWidth` が先勝ち**＝横長 Text は感情欄に入らない（`UI/ViewModels/Settings/VoiceEditorViewModel.cs:230-232`）＝一覧に「幅」「感情か」を載せないと本体側で振り分けられない。⑵ 数値の感情軸は上流に**無い**（caption 自由文＋絵文字 45 種）＝一覧に「caption」を Text で出すか定型集を出すかは製品判断。⑶ `max_ref_seconds` のように**checkpoint 依存の既定**があり、静的 JSON では版ずれする。⑷ `speaker_uncond_mode` 1 欄だけ HTTP に露出していない（`18` の差集合）。
- **本体が決めること**＝一覧の形（欄名・型・既定・範囲・単位・日本語ラベル・`IsEmotion`・`IsFullWidth`・露出可否）と、一覧の**版づけ**（本体と配布物の版が食い違ったときの扱い）。
- **受け入れ条件**＝`GET /params` が **1 回の呼び出しで全欄**を返し、各欄に `name/kind/default/min/max/choices/label_ja/is_emotion/is_full_width` が入っていること。**本体が露出する欄（現状 5＋改訂案 5）が 100% 含まれる**こと。応答は **≤ 100 ms**・**モデル未読込でも 200**（`/health` と同じくランタイム非依存）。

### 要求⑤ CPU 合成はできてもよい（遅さはケアしない）

- **事実**＝CPU 実測 RTF **3.27**（fp32・OMP=8・報告 §2-3）、10 steps でも 1.79（`13`）。参照ありは端から端まで 14.53→17.46（10 s）→19.81 s（30 s）＝RTF 3.86→5.20→6.04（`31` §5-2）。**bf16 は CPU で起動時 `ValueError`**（`inference_runtime.py:310`）＝CPU は fp32 必須。GPU が見えないと **fp32 は黙って CPU に落ちて 266.974 s／2 文字**（`29` §2-2）。
- **成立するか**＝**する**（速度をケアしないなら）。ただし**既定 fp32＋auto の組み合わせが「黙って CPU」を生む**。
- **制約・落とし穴**＝⑴ device と precision は**必ず 4 本セット**（`MODEL_DEVICE`／`CODEC_DEVICE`／`MODEL_PRECISION`／`CODEC_PRECISION`）。⑵ CPU 選択時に `PRELOAD=true` だと起動が 28 s 級で伸びる。⑶ CPU では `IRODORI_COMPILE_MODEL` が `cl` 不在で落ちる（`21` §3）＝触らない。
- **本体が決めること**＝GPU 不在機での既定挙動（bf16 で**止める**か、fp32 で**遅く動かす**か）。
- **受け入れ条件**＝CPU 選択で**合成が 200 で完了**し、**bf16 との取り違えで起動不能にならない**こと（precision 自動連動）。GPU 指定なのに CPU へ落ちたら **UI とログで必ず可視化**（現状 `/health` は設定値の echo で見えない・`29` §4）。

### 要求⑥ UI で GPU・CUDA 版・パラメータ・参照ボイスを試す／本体の読み上げは UI 指定の GPU・CUDA 版を暗黙に使う

- **事実**＝device は**プロセス起動時の env のみ**（`config.py:27-28`・`runtime.py:97-102`）＝要求ごとの GPU 指定は無い。1 プロセス 1 デバイス（`runtime.py:48`）。範囲外 index は**重みを載せる瞬間**に落ちる（`inference_runtime.py:657`／`codec.py:78`・6.07 s／11.28 s 後）で、`PRELOAD=true` なら**起動時に exit 3**・`false` なら**全合成 500**（`29` §1-3）。**掴んだ GPU は HTTP から確認できない**（`/health` は生 echo・`29` §4）。GPU 番号は CUDA／nvidia-smi／DXGI で体系が違い**再起動で変わりうる**＝安定鍵は UUID／PCI（`30` §3）。CUDA ビルドでも torch から `uuid`・`pci_bus_id` が取れる（`33`）。`nvidia-smi -L` は 0.04 s（NVIDIA 専用）。
- **成立するか**＝**する。ただし「UI で選んだものが本体の読み上げにも効く」ためには、Server を起こす主体が UI（配布アプリ）側でなければならない**。本体の元栓が起こすなら、本体が UI の設定檔を読むか、配布アプリが常駐して本体はポートに繋ぐだけにする。**ここは調査で決められない＝卓**。
- **制約・落とし穴**＝⑴ **CUDA 版の切替は再起動では済まない**＝cu126 と cu130 は別の site-packages 木（DL 2,470／1,781 MiB・導入後 `torch/` 3,937／2,554 MB）＝UI で切り替えるなら**両方同梱（実行系 ≈4.4 GiB）か、初回にネットで取得**。⑵ GPU の切替は**プロセス再起動**（モデル再読込 11〜28 s）。⑶ 起動直後・初見形状のスパイク（同文連射でも 1 発目 40.8 s・3 発目 19.4 s・`19` §2-2）＝UI の「試す」でウォームしても、本体の読み上げが別プロセスなら効かない。⑷ ROCm を残す場合は可視化変数が `HIP_VISIBLE_DEVICES` に変わる（`29` §2-1）。
- **本体が決めること**＝起動主体（本体の元栓 vs 配布アプリ常駐）・GPU の同定鍵（index vs UUID／PCI）・cu126/cu130 の持ち方・本体の読み上げ中に UI から設定を変えられるか（変えたら再起動＝配信中の無音）。
- **受け入れ条件**＝UI で GPU を選んで**再起動から ready まで ≤ 60 s**（3090・SSD・bf16）、**掴んだ GPU の名前と UUID が UI に表示**され、選び損ねたら**起動時に失敗として見える**（黙って CPU に落ちない）こと。CUDA 版の切替は**同一 UI 操作で完結**し、切替後 1 発目の合成が **≤ 40 s**（スパイク上限）・以後 warm で RTF ≤ 0.25（短文 40 steps）。

### 要求⑦ 参照ボイスファイル＋名付けのペアで話者とする

- **事実**＝話者の実体は `VoiceSpec`（`voices.py:27-35`）＝`ref_wav`／`ref_wavs`／`ref_latent`／`ref_latents`／`ref_embed`／`no_ref` の 6 択。登録経路は 3 つ＝檔名スキャン（stem がそのまま名前）・`voices.json` alias（**任意のキー**・alias がスキャンを上書き）・要求で `irodori.ref_wav` 直指定（voice 解決を丸ごと飛ばす・`app.py:418-459`）。**日本語名は alias／檔名／`DEFAULT_VOICE` で通る**が **CRUD API は ASCII のみ**（本便 実射 2・3・6〜12）。本体の現行は `ywk-<sha256 先頭12>` の自動登録（`IrodoriConstants.cs:403-413`）。参照は 10〜30 s が推奨レンジ・上限 120 s（`31` §1-3）。**参照を当てると出力尺が短くなる**（94.3→82.4 フレーム・`31` §8）。**参照潜在のキャッシュは一切なく、チャンクごとに符号化し直す**（`31` §3）。
- **成立するか**＝**する。ただし「名付け」を日本語にするなら CRUD API は使えず、`voices.json` を配布アプリが直接書く**（または新リポが独自の登録口を持つ）。
- **制約・落とし穴**＝⑴ 名前と参照ファイルの対応は `voices.json` にしか残らない＝**「話者メタ（表示名・キャプション既定・作成日・元ファイル）を置く場所が上流に無い」**。⑵ 一覧 API が**絶対パスを漏らす**（実射 1）。⑶ 同名衝突は alias 優先で**黙って上書き**。⑷ 中身の検証が無い＝壊れた wav は合成時に初めて落ちる（`voices.py:119-127`）。⑸ 本体の `ywk-` 自動登録と配布アプリの名付けが**同じ `voices/` を奪い合う**。
- **本体が決めること**＝話者の所有者（本体 vs 配布アプリ）・話者メタの置き場・日本語名を許すか（許すなら CRUD API は使わない）・参照潜在キャッシュを持つか（§10-4 の 13）。
- **受け入れ条件**＝UI で「wav を選ぶ＋名前を付ける」の **2 操作**で話者が増え、**本体の一覧に即反映**（走査はキャッシュ無し＝再起動不要）。日本語・空白・記号を含む名前で**合成が 200**。参照あり短文（3090・bf16・40 steps）で **RTF ≤ 0.34**、参照潜在を使うなら**増分 ≤ +6 %**（`33`）。

### 要求⑧ 参照ボイスなしは話者名「デフォルト」

- **事実**＝`no_ref` の入口は 2 つ＝`NO_REF_IDS`＝`{"none","no_ref","no-ref","null","text-only"}`（`voices.py:23`・小文字化して一致）と、**alias に `{"no_ref": true}` を書く道**。「デフォルト」は前者に**入っていない**が、後者で成立する（実射 4）。しかも alias 経路は `allow_no_ref_voice=false` でも封じられない（実射 13）。`IRODORI_DEFAULT_VOICE=デフォルト` も通る（実射 12）。参照なしの声＝Irodori 自身の声（caption のみ）で、司令官の耳検分済み（`35` 追記）。
- **成立するか**＝**する**（配布物の `voices.json` に 1 行足すだけ）。
- **制約・落とし穴**＝⑴ 利用者が `voices/` に `デフォルト.wav` を置くと**スキャンより alias が勝つ**ので事故は起きないが、逆に**利用者が「デフォルト」を参照つきに変えられない**。⑵ 「none」も同時に一覧に出る（`allow_no_ref_voice=true` の副作用）＝話者一覧に**利用者が知らない名前が 1 つ増える**。⑶ 参照なしと参照ありで**尺が変わる**（§⑦）。
- **本体が決めること**＝「デフォルト」の綴り（全角／半角・別名を許すか）・`none` を一覧から隠すか（`allow_no_ref_voice=false` にすると alias 経路だけが残る＝実射 13・13b）。
- **受け入れ条件**＝話者一覧の**先頭に「デフォルト」1 件**が必ず存在し、`voices/` が空でも合成が 200。一覧に上流由来の余計な id（`none`）が**出ない**こと。
